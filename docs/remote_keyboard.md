# リモートキーボード (別の端末に PC-98 のキーボードを出す)

QuuBee の入力バーの Remote ボタン (⌨) で QR を出し、タブレットやスマホのカメラで読むと、その端末のブラウザに
PC-98 のキーボードが開く。そこで押したキーが QuuBee のゲストへ届く。

- 受け手: QuuBee のページ (`web/index.html` + `web/player/remote-host.js`)
- 送り手: `/remote/#r=<部屋>` (`web/remote/`。QR から開く。noindex)
- 元: へちま言語ラボの `/remote/` (hechima repo `docs/remote.md`)。回線の作りはそのまま借り、送るものを
  「PC-98 のキーコード」にし、受け手 1 台に送り手を複数つなげる形 (二人プレイを見込む) へ広げた

## 考え方: 「理想的な PC-98 キーボード」

送り手が送るのは KeyboardEvent の `code` ではなく **PC-98 のキーコード (NKEY 0x00〜0x7F) そのもの**。受け手は
`PC98_KEYMAP` の翻訳を通さずにキー押下の合流点 (`keyHub`) へ注ぐ。だから XFER・NFER・カナ・GRPH・STOP・COPY・
HELP・VF1〜5・テンキーの `=` と `,` が、対応表を足さずにそのまま届く。

**ホストの物理キーボードの経路には PC-98 固有キーを足さない** (ユーザー判断 2026-10-09)。物理キーボードの経路
(FEP・IME 欄・Ctrl ショートカットの除外・モーダル中の遮断) とリモートは独立している。

## キー押下の合流点 (keyHub、`bridge.js`)

ゲストの 1 つのキーを押す元は複数ありうる。元ごとに押下を覚え、最初の元が押したときだけ keyDown、最後の元が
離したときだけ keyUp を送る。元の名前 = `kbd:<KeyboardEvent.code>` / `pad` / `remote:<端末 id>`。

- 旧来は「パッドとキーボードで同じキーを押すと、片方を離した時点でゲスト側も離れる」のを許容していた。
  リモートが CAPS・カナを押し続けるようになると許容できないのでここで断った。副産物として、物理キーボードの
  左右 Shift (同じ 0x70) の片方を離しても押したままになった
- リピート (`repeat`) は同じ元が押しているときだけ再 down を送る (NP2kai は押下中のキーへの再 down を break+make
  として扱う)。FEP の編集キー (1 打だけ) は `tap`: 他の元が押していれば再 down で 1 打を作る
- 物理キーボード・パッドは blur / タブ非表示 / モーダルで自分の元だけを離す。リモートの元はこれらで離さない
  (keyup を取りこぼさないので止める理由が無い。CAPS・カナのロックを途中で外すほうが害がある)
- `qbDebug.keys()` で中身 (NKEY → 押している元) が見える

## 送り手のキーの振る舞い (`web/remote/keyboard.js`)

- ふつうのキー: 押している間だけ押下。長押しでオートリピート (500ms 後に 50ms 間隔で `r: 1` 付きの再 down)。
  指を滑らせると隣のキーへ移る (カーソル・テンキーで動かすゲーム向け。修飾・ロックへは移らない)
- SHIFT・CTRL・GRPH: 押しながら他のキーを打てる (マルチタッチ)。単独で短く (400ms 未満) タップすると、次の 1 打
  だけ押したまま (ラッチ)。ラッチ中にもう一度タップすると外れる
- CAPS・カナ: 実機と同じ**機械式ロック**。1 回目のタップで押し下げたまま、2 回目で離す。NP2kai の既定のキー表は
  0x71/0x72 をメカニカル扱いにしていない (down = 倒れる・up = 起きる) ので、送り手が押し続けるのが正しい
- 回線が開くたびに、押し下げたままのキー (ロック・ラッチ・押している指) を送り直す
- 閉じる (pagehide) ときは回線を明示的に閉じる。閉じないと受け手は ICE の時間切れまで気づかない (検査で発見)
- 盤面は `web/remote/layouts/<id>.json` から描く (キー名は NP2kai の `keystat.tbl` の `s_keyname`)。
  `#r=<部屋>&l=<id>` で選べる。現在は `pc98-full` (フルキーボード・テンキー付き) だけ

## FEP (日本語入力) との連携 (2026-10-10、段階 A)

FEP が ON の間、受け手 (`bridge.js` の `remoteRoute`) は届いた NKEY を物理キーボードと同じ KeyTap に組み立て直して
`fep.feed` / `feedUp` に通し、飲まれなかったキーだけを keyHub へ注ぐ。変換エンジンは受け手・キーボードは
「理想的な PC-98 キーボード」のまま (へちま言語ラボの `/remote/` と同じ分け方)。

- `code` = JIS 配列の位置 (`@` = BracketLeft・`]` = Backslash・`¥` = IntlYen・`_` = IntlRo・XFER = Convert・
  NFER = NonConvert)。`key` = PC-98 の刻印 (SHIFT・CAPS は端末ごとに覚える)
- **CTRL+XFER で FEP の ON/OFF** (実機の FEP の標準)。ゲストへは送らない
- **XFER = 変換** (スペースとして渡す、WX 流)。ただし NICOLA の JIS レイアウトでは XFER は右親指なのでそのまま渡す
  (FEP は未確定中に知らないキーを飲むので「XFER で試して駄目ならスペース」はできない)
- カナロック中は FEP を通さない (実機で FEP を使わずにカナを倒したときと同じく半角カナが直接入る)
- 押したときに FEP が飲んだキーは、離すときも FEP へ (ゲストに解放だけが届かないように)
- **扱わない** (疑似 FEP なのでここまで、ユーザー判断): WX / ATOK のキーの作法の違い (ATOK の XFER 単押し等)・
  NFER の意味・カナキーでの JIS かな入力・最下行のモード表示

## 回線

WebRTC DataChannel (順序保証・再送あり・DTLS)。同じ LAN ならホスト候補で直結する。STUN (`stun.cloudflare.com`)
は候補を足すだけで、TURN は持たない = **押したキーは必ず端末間を直接流れる** (同じ LAN でないとつながらない)。

最初の SDP の受け渡しだけ中継を通す (`relay/worker.js` = Cloudflare Worker `quubee-relay` + Durable Object。
ローカルは `tools/devserver.js` の代役。デプロイは [deploy.md](deploy.md))。

- `wss://<relay>/api/pair/<room>?role=host|kbd&id=<端末 id>&sid=<読み込みごとの id>`
- 部屋 = Durable Object 1 個 = **受け手 1 + キーボード 4 まで**・**何も保存しない**・1 メッセージ 16KB まで・
  Origin を見る。入退室のたびに `{ t: "peers", list: [{ id, role, sid }] }` を全員へ
- 端末 → `{ to, t: "offer"|"answer", sdp }` → 中継が宛先へ `{ from, ... }` で流す
- 同じ id が入り直したら古い接続を 4001 で閉じる (閉じられた側はつなぎ直さない)。受け手は 1 台だけ (後から
  開いたタブが勝つ)
- 部屋の名前は受け手が乱数 (16 バイト) で作り、QR の URL のフラグメント (`#r=`) に載せる。受け手は
  localStorage (`quubee_remote_v1`) に部屋と ON/OFF を覚え、**読み込み直しても中継へつなぎ直す** (Stop で止める
  まで)。キーボードは自分の id を `quubee_remote_kbd_id` に覚える
- 受け手は sid が変わったキーボード (読み込み直した) に offer を出し直す。直接の回線が生きていれば、中継から
  抜けても (iOS が裏で WebSocket を切る等) そのまま使う

### DataChannel のメッセージ (JSON)

| 向き | メッセージ | 意味 |
|---|---|---|
| 送り手 → 受け手 | `{ t: "hello", v: 1, layout }` | 回線が開いたら最初に 1 通 |
| 送り手 → 受け手 | `{ t: "key", d: 1\|0, k, r?: 1 }` | 押した / 離した。`k` = NKEY (0〜127 の整数だけ通す)。`r` = オートリピート |

受け手は形を検査してから通す (`remote-host.js` の `onMessage`)。回線が切れたら (DataChannel の close /
ICE の failed)、その端末が押していたキーをすべて離す。

## 検査

`tools/browser/remote_check.js` (ヘッドレス Chromium の 2 ページ + devserver の代役)。物理キーボードの合流 (左右
Shift)・接続・XFER・CAPS のロック・SHIFT のラッチ・キーボードの読み込み直し・QuuBee の読み込み直し・閉じたら
離れる。**見えないもの**: 2 台が同じ Wi-Fi で直結できるか (mDNS・クライアント分離) と本番の中継は実機でしか
分からない。
